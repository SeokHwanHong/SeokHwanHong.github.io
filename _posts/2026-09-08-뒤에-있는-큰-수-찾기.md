프로그래머스 Lv.2 **뒤에 있는 큰 수 찾기** 풀이 기록이다. 각 원소의 오른쪽에서 자신보다 크면서 가장 가까운 값을 찾아야 하며, 없으면 `-1`을 넣는다.



## 처음 접근: 오른쪽을 직접 탐색하기

처음에는 각 위치에서 오른쪽 원소를 하나씩 확인하는 방식으로 생각할 수 있다. 하지만 배열 길이가 최대 1,000,000이므로, 원소마다 뒤쪽을 끝까지 찾으면 최악의 경우 `O(N²)`가 된다.

초기 코드에는 시간 복잡도 외에도 다음 문제가 있었다.

- 반복 중 `numbers.remove(...)`로 원본 배열을 바꾸면, `for`문이 기준으로 삼는 인덱스와 실제 배열 인덱스가 어긋난다.
- 매 반복마다 `max(numbers)`를 계산하면 그 자체로도 `O(N)`이 추가된다.
- 다음 값을 찾을 때는 `current_index`를 증가시켜야 하는데, 현재 값 자체를 증가시키고 있었다.

따라서 이미 답을 찾지 못한 인덱스만 기억해 두고, 더 큰 값이 나타나는 순간 한꺼번에 답을 확정하는 방식이 필요하다.

## 핵심: 인덱스를 저장하는 단조 감소 스택

스택에는 아직 뒷 큰 수를 찾지 못한 **인덱스**를 넣는다. 스택에 쌓인 값은 아래에서 위로 갈수록 작아지지 않는 순서가 되도록 유지한다.

새 값 `numbers[i]`가 들어왔을 때 스택의 맨 위 값보다 크다면, 그 맨 위 인덱스의 뒷 큰 수는 현재 값으로 확정된다. 더 이상 그 인덱스의 오른쪽을 탐색할 필요가 없으므로 스택에서 꺼낸다.


### 최종 코드

```python
def solution(numbers):
    answer = [-1] * len(numbers)
    stack = []

    for i, current_num in enumerate(numbers):
        # 현재 값보다 작은 원소들은 현재 값을 뒷 큰 수로 확정한다.
        while stack and numbers[stack[-1]] < current_num:
            idx = stack.pop()
            answer[idx] = current_num

        # 아직 뒷 큰 수를 찾지 못한 현재 인덱스를 보관한다.
        stack.append(i)

    return answer
```

## 동작 예시

`numbers = [2, 3, 3, 5]`를 생각해 보자.

1. `2`의 인덱스 0을 스택에 넣는다.
2. `3`을 만나면 스택 맨 위의 `2`보다 크므로, `answer[0] = 3`으로 확정한다.
3. 다음 `3`은 스택 맨 위의 `3`보다 크지 않으므로 그대로 쌓는다. 같은 값은 뒷 큰 수가 아니기 때문이다.
4. `5`를 만나면 스택의 두 `3`보다 크므로 두 인덱스를 차례로 꺼내 `5`를 넣는다.

마지막까지 스택에 남은 인덱스는 더 큰 수를 만나지 못한 경우이므로, 초기값 `-1`을 그대로 사용하면 된다.

## 복잡도

각 인덱스는 스택에 한 번 들어가고 최대 한 번만 나온다. 따라서 전체 시간 복잡도는 `O(N)`, 추가 공간 복잡도는 `O(N)`이다.

이 문제의 핵심은 “현재 값을 기준으로 오른쪽을 다시 찾는 것”이 아니라, **현재 값이 이전에 보류했던 원소들의 답을 확정하는 순간**이라는 점이다.
