## 9월 17일 학습 내용

프로세스의 실행 순서를 결정하는 CPU 스케줄링, 교착상태와 기아의 차이, 메모리 관리와 페이지 교체를 정리했다. 원문에서 혼동된 개념은 구분하고, 네트워크 주소 관련 메모는 별도 항목으로 분리했다.

## 프로세스 상태와 선점

프로세스는 실행 중인 프로그램이다. 기본적인 상태 전이는 다음과 같다.

| 상태 전이 | 발생 상황 |
| --- | --- |
| 준비 → 실행 | 스케줄러가 선택한 프로세스에 CPU를 할당 |
| 실행 → 준비 | 시간 할당량 소진 등으로 CPU 사용을 중단 |
| 실행 → 대기 | 입출력 완료나 특정 사건을 기다림 |
| 대기 → 준비 | 기다리던 입출력이나 사건이 완료됨 |
| 실행 → 종료 | 작업을 마침 |

선점형은 운영체제가 실행 중인 프로세스의 CPU 사용권을 회수할 수 있는 방식이다. 비선점형은 프로세스가 종료되거나 입출력 요청 등으로 CPU를 스스로 내놓을 때까지 실행을 이어간다. 비선점형이라고 해서 프로세스가 항상 종료까지 실행되는 것은 아니다.

선점 여부는 CPU 사용권을 회수하는 정책으로 구분한다. 도표의 실선·점선이나 저장장치가 자기 드럼인지 여부만으로 판단하지 않는다.

## CPU 스케줄링 비교

| 방식 | 선택 기준 | 선점 여부 | 주의할 점 |
| --- | --- | --- | --- |
| FCFS | 먼저 도착한 작업 | 비선점 | 긴 작업 뒤의 짧은 작업들이 오래 기다리는 호위 효과 |
| SJF | 다음 CPU 실행 시간이 짧은 작업 | 비선점 | 실행 시간 예측이 필요하며 긴 작업의 기아 가능 |
| SRTF 또는 SRT | 남은 CPU 실행 시간이 가장 짧은 작업 | 선점 | 더 짧은 작업이 도착하면 현재 작업을 선점할 수 있음 |
| RR | 준비 큐의 순서대로 일정 시간씩 실행 | 선점 | 시간 할당량에 따라 응답성과 문맥 교환 비용이 달라짐 |
| 우선순위 | 우선순위가 높은 작업 | 구현에 따라 다름 | 낮은 우선순위 작업이 계속 밀릴 수 있음 |
| HRN | 응답비가 가장 큰 작업 | 비선점 | 대기 시간이 길수록 선택될 가능성이 커짐 |

FCFS는 FIFO 큐 방식으로 동작한다. 앞선 작업 때문에 오래 기다리는 현상 자체가 교착상태를 의미하지는 않는다.

RR은 새 작업이 도착할 때마다 남은 시간이 가장 짧은 작업을 선택하는 방식이 아니다. 각 작업에 시간 할당량(time quantum)을 주고, 시간이 끝났는데 작업이 남아 있으면 준비 큐의 뒤로 보낸다.

HRN의 응답비는 다음과 같이 계산한다.

`응답비 = (대기 시간 + 서비스 시간) / 서비스 시간`

모든 작업이 처음부터 준비되어 있고 문맥 교환 비용과 입출력을 무시하면, 실행 순서를 바꾸어도 전체 CPU 작업량은 같다. 그러나 작업별 대기 시간과 반환 시간은 달라지므로, FCFS와 SJF의 성능이 같다는 뜻은 아니다.

## 교착상태와 기아

| 구분 | 의미 | 예시 |
| --- | --- | --- |
| 교착상태(Deadlock) | 서로가 보유한 자원을 기다리며 관련 작업들이 진행하지 못함 | A는 B의 자원을, B는 A의 자원을 기다림 |
| 기아(Starvation) | 다른 작업에 계속 밀려 특정 작업이 자원을 할당받지 못함 | 높은 우선순위 작업이 계속 도착하여 낮은 우선순위 작업이 대기 |

기아를 완화하는 방법 중 하나가 에이징(Aging)이다. 대기 시간이 길어진 작업의 우선순위를 점진적으로 높인다.

### 교착상태의 네 가지 필요조건

1. **상호배제**: 한 자원을 동시에 여러 프로세스가 사용할 수 없다.
2. **점유와 대기**: 자원을 가진 채 다른 자원을 기다린다.
3. **비선점**: 보유 자원을 강제로 회수할 수 없다.
4. **환형대기**: 자원을 기다리는 관계가 고리를 이룬다.

여기서 비선점은 자원 회수에 관한 조건이다. CPU 스케줄링을 선점형으로 바꾼다고 모든 교착상태가 해결되는 것은 아니다.

### 대응 전략

- **예방**: 네 가지 필요조건 중 하나가 성립하지 않도록 설계한다.
- **회피**: 자원 할당 후에도 안전한 상태인지 판단한다. 대표적인 방법이 은행원 알고리즘이다.
- **탐지**: 교착상태 발생 여부를 검사한다.
- **회복**: 탐지 후 프로세스 종료나 자원 회수 등으로 상태를 해소한다.

## 메모리 관리

### 페이징과 세그멘테이션

| 구분 | 페이징 | 세그멘테이션 |
| --- | --- | --- |
| 분할 기준 | 일정한 크기의 페이지 | 코드·데이터·스택 등 논리적 단위 |
| 크기 | 고정 크기 | 가변 크기 |
| 대표적인 단편화 | 내부 단편화 | 외부 단편화 |

NTFS와 FAT는 파일 시스템이다. 각각을 세그멘테이션·페이징과 일대일로 대응시키는 것은 올바른 구분이 아니다.

### 페이지 부재와 교체

요구 페이징에서 필요한 페이지가 현재 주기억장치에 없으면 페이지 부재(page fault)가 발생한다. 운영체제는 필요한 페이지를 가져오고, 사용할 빈 프레임이 없다면 기존 페이지를 교체할 수 있다. 따라서 페이지 부재와 페이지 교체는 같은 뜻이 아니다.

| 알고리즘 | 교체 대상 |
| --- | --- |
| FIFO | 가장 먼저 적재된 페이지 |
| LRU | 가장 오랫동안 참조되지 않은 페이지 |
| OPT | 앞으로 가장 늦게 다시 참조될 페이지 |

OPT는 미래의 참조 순서를 알아야 하므로 주로 비교 기준으로 사용한다.

### 벨레이디의 모순

FIFO에서는 같은 페이지 참조열에 대해 할당 프레임 수를 늘렸는데도 페이지 부재 횟수가 증가할 수 있다. 이를 벨레이디의 모순(Belady's anomaly)이라고 한다. 메모리를 더 주면 모든 교체 정책에서 반드시 페이지 부재가 줄어드는 것은 아니라는 점이 핵심이다.

## 네트워크 주소 메모

- Windows에서 `ipconfig`는 IP 설정을 확인할 때 사용한다. MAC 주소 등 상세 정보는 `ipconfig /all`에서 확인한다.
- MAC 주소를 물리적 주소라고 부르지만, 운영체제의 물리 메모리 주소와는 다른 개념이다.
- ARP는 같은 링크에서 IPv4 주소에 대응하는 MAC 주소를 알아내는 데 사용한다.
- RARP는 MAC 주소를 바탕으로 IP 주소를 알아내던 과거의 프로토콜이다.

원문에는 네트워크 라우팅 기초의 제목만 있어, 구체적인 라우팅 실습 내용은 추가하지 않았다.
