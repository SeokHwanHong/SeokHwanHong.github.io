## 이번 주에 한 일

이번 주에는 웹 화면을 구현하는 것에서 출발해 웹 데이터를 수집하고, 이를 배열로 다루며, Django로 웹 애플리케이션을 구성하는 흐름까지 학습했다.

먼저 HTML·CSS·JavaScript로 일반 계산기와 공학용 계산기를 구현했다. `prompt`로 입력을 받고 HTML 요소와 CSS를 조합해 화면을 구성하면서, 화면을 만드는 일과 입력된 수식을 계산하는 로직은 분리해서 생각해야 한다는 점을 확인했다.

이후에는 `requests`, `BeautifulSoup`, `Selenium`을 사용해 웹페이지에서 데이터를 가져오는 방식을 익혔다. 정적인 HTML은 `requests`와 `BeautifulSoup`으로 파싱하고, JavaScript 실행이나 지연 로딩이 필요한 화면은 Selenium으로 브라우저를 제어하는 차이를 비교했다. CSS 선택자와 XPath를 이용해 원하는 요소를 찾고, 동적 페이지에서는 로딩 시점을 기다린 뒤 값을 가져오는 과정도 실습했다.

NumPy에서는 리스트와 달리 배열 전체에 연산을 적용하는 벡터화 방식을 다뤘다. 배열의 형태를 확인하고, `zeros`, `ones`, `arange`, `linspace`로 배열을 만들었다. 특히 불리언 마스킹을 이용해 조건에 맞는 값만 선택하거나 변경하는 방법을 익혔다.

주 후반에는 Django 개발 환경을 설정했다. 가상환경에서 Django를 설치한 뒤 프로젝트와 앱을 구성하고, `views.py`의 함수와 `urls.py`의 경로를 연결해 응답을 반환하는 기본 흐름을 확인했다. 템플릿 경로와 시간·언어 설정도 함께 살펴보며, 웹 애플리케이션이 여러 파일과 설정으로 구성된다는 점을 이해했다.

## 인상 깊었던 점

이번 주에는 웹페이지를 만드는 일과 데이터를 다루는 일이 하나의 흐름으로 이어져 있다는 점이 인상적이었다.

HTML·CSS·JavaScript는 사용자가 보는 화면과 동작을 만든다. Selenium은 브라우저가 실제로 렌더링한 화면에서 필요한 정보를 찾고, NumPy는 가져온 값을 효율적으로 계산할 수 있는 배열 형태로 바꾼다. Django는 다시 이 결과를 사용자에게 제공할 수 있는 웹 애플리케이션의 구조를 만든다.

도구마다 역할은 다르지만, 결국 데이터가 어디에서 생성되고 어떤 형태로 이동하며 누구에게 보여지는지를 연결해서 생각해야 한다는 점을 배웠다.

## 어려웠던 점과 배운 점

웹 데이터 수집에서는 무조건 Selenium을 사용하는 것이 아니라, 페이지가 정적으로 제공되는지와 JavaScript 실행이 필요한지를 먼저 판단해야 했다. 동적 페이지에서는 스크립트가 모두 로드되기 전에 요소를 찾으면 값이 비어 있을 수 있어, 필요한 경우 대기 처리와 선택자를 함께 설계해야 했다.

NumPy의 불리언 마스킹도 문법 자체보다 조건식의 결과가 배열의 각 원소와 대응된다는 원리를 이해하는 것이 중요했다. 반복문 없이도 조건에 맞는 데이터를 골라낼 수 있어, 이후 데이터 전처리와 분석에 직접 활용할 수 있겠다고 느꼈다.

Django는 파일과 설정이 많아 처음에는 구조가 복잡하게 느껴졌다. 하지만 가상환경으로 의존성을 분리하고, URL → View → Template의 흐름으로 나누어 보니 각 파일의 역할을 조금씩 구분할 수 있었다.
