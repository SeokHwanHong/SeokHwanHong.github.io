## 이번 주에 한 일

이번 주에는 HTML·CSS·JavaScript를 활용해 계산기를 구현하고, 웹에서 데이터를 가져오는 Scraping과 Crawling의 기본 흐름을 학습했다.

계산기 실습에서는 `prompt`로 입력을 받고, HTML 요소와 CSS 스타일을 조합해 화면을 구성했다. 일반 계산기와 공학용 계산기를 구현하면서 단순히 버튼을 배치하는 것을 넘어, 입력된 수식을 어떻게 해석하고 결과로 연결할지 고민했다.

이후에는 `requests`, `BeautifulSoup`, `Selenium`을 활용해 웹페이지에서 데이터를 가져오는 방법을 정리했다. 정적인 HTML 구조를 파싱하는 방법과 실제 브라우저를 제어해야 하는 상황의 차이도 함께 확인했다.

## 인상 깊었던 점

이번 주에는 웹페이지를 만드는 과정과 웹페이지에서 데이터를 읽어오는 과정이 이어져 있다는 점이 인상적이었다.

HTML·CSS·JavaScript는 사용자가 보는 화면과 동작을 만들기 위한 도구라면, Crawling은 그 화면 뒤에 있는 HTML 구조를 읽어 필요한 정보를 데이터로 바꾸는 과정이었다. 같은 웹페이지라도 어떤 목적을 갖고 접근하느냐에 따라 전혀 다른 방식으로 활용할 수 있다는 점을 배웠다.

## 어려웠던 점과 배운 점

계산기 구현에서는 화면 구성과 계산 로직을 분리해서 생각해야 했다. 버튼과 스타일을 만드는 일은 눈에 바로 보이지만, 입력값을 받아 수식을 처리하는 부분은 별도의 논리가 필요했다.

Crawling에서도 단순히 코드를 실행하는 것보다, 페이지 구조를 먼저 확인하고 어떤 태그와 선택자를 기준으로 데이터를 가져올지 결정하는 과정이 중요했다. 또한 요청을 과도하게 보내면 차단될 수 있으므로, 기술적으로 가능하더라도 사이트 정책과 요청 간격을 지켜야 한다는 점을 함께 배웠다.

## 다음 주에 해볼 것

- 계산기 코드를 함수 단위로 나누어 다시 구현하기
- 정적 페이지는 `requests`와 `BeautifulSoup`으로 먼저 분석해보기
- JavaScript로 생성되는 페이지에서만 Selenium을 사용하는 기준 세우기
- 수집한 데이터를 DataFrame으로 정리하는 과정까지 연결하기

화면을 구현하는 경험과 데이터를 수집하는 경험이 따로 떨어진 것이 아니라는 점을 기억하면서, 다음 주에는 웹 데이터를 분석 가능한 형태로 만드는 단계까지 확장해보고 싶다.
