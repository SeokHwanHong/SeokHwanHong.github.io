2025 인하 인공지능 챌린지 대학원 부문에서 흑백 이미지와 자연어 설명을 함께 받아 색채 이미지를 생성한 프로젝트다. 팀명은 **5층**이며, 팀원은 이지호·고영호·박민수·홍석환이다. 팀은 **대학원 부문 우수상**을 수상했다.

색채화와 초해상도를 분리하고, L-CAD가 생성한 색채 이미지를 서로 다른 복원 모델로 처리해 대회 점수를 비교했다. 최종적으로 SwinIR 2배 복원을 선택했고, 공개 평가 0.6830과 비공개 평가 0.6925를 기록했다.

## 1. 프로젝트 배경과 목표

흑백 이미지의 윤곽만으로 원래 색을 하나로 결정하기는 어렵다. 캡션에 색과 객체의 단서가 있으면 이를 함께 읽어야 한다. 예를 들어 발표자료의 캡션에는 노란 간판, 빨간 글씨, 흰 티셔츠, 빨강·흰색·파랑 깃발이 등장한다. 같은 이미지 안에서 각각의 단서를 해당 객체에 연결하는 것이 과제였다.

대회는 생성 이미지가 원본의 색 분포와 비슷한지, 캡션의 의미를 반영하는지를 함께 평가했다.

| 평가 항목 | 의미 | 가중치 |
| --- | --- | ---: |
| HSV Similarity | 실제 색채 이미지와 생성 이미지의 HSV 히스토그램 유사도 평균 | 0.6 |
| CLIP Score | 캡션과 생성 이미지 간 코사인 유사도, ViT-L-14 사용 | 0.4 |

최종 점수는 `0.6 × HSV Similarity + 0.4 × CLIP Score`다. 따라서 선명해 보이는 출력만으로 모델을 선택할 수 없었다. 색 분포와 텍스트 정합성을 포함한 최종 대회 점수를 확인해야 했다.

## 2. 데이터와 실험 범위

| 구분 | 수량 | 구성 |
| --- | ---: | --- |
| 학습 자료 | 65,260장 | 흑백 입력, 정답 색채 이미지, 이미지 경로와 캡션 |
| 평가 자료 | 200장 | 흑백 입력, 캡션, 샘플 ID |
| 입력 해상도 | 512×512 | 색채화 단계에서 256×256으로 축소 |
| 최종 파이프라인 출력 | 512×512 | SwinIR 2배 복원 결과 |

학습 자료가 제공됐지만 이번 프로젝트는 **사전학습 모델의 추론만 수행**했다. 65,260장으로 모델을 재학습한 결과로 해석하면 안 된다. 실험의 초점은 색채화 모델과 복원 모델을 연결하고, 후보 조합의 출력과 제출 점수를 비교하는 데 있었다.

## 3. 기준 접근과 두 단계 파이프라인

### Canny·ControlNet·Stable Diffusion 기준 접근

발표자료의 기준 접근은 흑백 이미지에서 Canny edge를 추출하고, ControlNet으로 구조 조건을 전달하며, 캡션을 함께 입력하는 Stable Diffusion 추론이다. VAE가 이미지와 잠재 표현을 연결하고, 역확산 과정에서 색채 출력을 생성한다.

발표자료에 기록된 기준 설정은 `guidance scale = 7.5`, `inference steps = 50`이다. 이는 **기준 접근의 설정**이며, 저장소에 포함되지 않은 L-CAD 실행의 설정값으로 간주하지 않는다. 기준 접근의 별도 점수가 자료에 없으므로 최종 방식과의 개선 폭은 계산할 수 없다.

### L-CAD 색채화와 SwinIR 복원

최종 처리 순서는 다음과 같다.

1. 512×512 흑백 이미지를 256×256으로 축소한다.
2. L-CAD에 흑백 이미지와 캡션을 입력해 256×256 색채 이미지를 만든다.
3. SwinIR로 2배 복원해 512×512 출력을 얻는다.
4. 평가 ID에 맞춘 이미지와 CLIP 임베딩 CSV를 함께 압축한다.

내가 맡은 일은 색채화 결과를 초해상도 입력으로 연결하고, 복원 후보를 실행해 최종 제출물까지 구성하는 작업이었다. 서로 다른 태스크를 하나의 처리 과정으로 연결하는 일이 어려웠다. 색채화와 복원을 각각 설명하는 것에 더해, 앞 단계의 결과를 다음 단계에서 사용하고 제출 형식까지 이어야 했기 때문이다. 현재 공개 코드의 RGB 변환·이미지 저장·ID별 이미지 읽기는 이 연결을 확인할 수 있는 부분이다. 다만 이를 특정 크기·자료형·파일명 오류를 당시 발견하고 해결했다는 사례로 바꾸지는 않았다.

L-CAD는 자연어 설명의 정보량이 서로 다른 상황을 다루는 색채화 모델이다. 논문은 사전학습 생성 모델의 색채 사전정보와 언어 이해를 활용하고, 입력의 국소 구조를 보존하는 모듈 및 객체를 고려한 샘플링을 제안한다. 이 프로젝트에서는 사전학습 모델을 추론에 사용했다. [L-CAD 논문](https://arxiv.org/abs/2305.15217)

발표자료에는 128×128과 256×256 색채화 출력이 함께 제시돼 있다. 두 결과는 해상도 선택 과정을 보여주는 정성적 예시이며, 해상도별 점수나 처리 시간은 기록돼 있지 않다.

## 4. 초해상도 후보 비교와 선택

색채화 이후 Real-ESRGAN, SwinIR, ResShift를 비교했다. Real-ESRGAN은 GAN 기반 복원 모델이고, SwinIR은 Swin Transformer 기반 복원 모델이다. ResShift는 잔차 이동을 사용하는 확산 기반 초해상도 모델이다.

당시에는 2배·4배 복원을 비교하려 했다. 내 기억으로 입력을 축소할 때는 동일한 보간 방식을 적용했지만, 시도한 4배 설정에서는 기대한 성능을 얻지 못했다. 아래는 남아 있는 후보별 제출 점수다. 같은 보간 방식을 썼다는 설명이 모든 모델의 입력·출력 조건까지 같았다는 의미는 아니다.

| 모델 | 발표자료의 배율 | 공개 평가 | 비공개 평가 |
| --- | ---: | ---: | ---: |
| Real-ESRGAN | 2배 | 0.6700 | 미기록 |
| **SwinIR** | **2배** | **0.6830** | **0.6925** |
| ResShift | 4배 | 0.6652 | 미기록 |

후보의 출력과 제출 점수를 비교한 뒤 SwinIR 2배 복원 조합을 최종 제출에 사용했다. 공개 점수는 Real-ESRGAN보다 0.0130, ResShift보다 0.0178 높았다. **기록된 제출 후보 중 가장 높은 Public 점수를 보인 조합을 선택했다**는 의미다. 배율과 크기 처리 등 비교 조건이 달라 이 차이를 모델 구조나 복원 배율 하나의 효과로 단정하지 않는다. 비공개 점수도 SwinIR만 기록돼 있다.

보간 알고리즘, 모델별 축소·입력 크기, 4배 출력의 최종 크기 조정 과정, 모든 후보에 동일한 색채화 출력을 사용했는지는 원본 코드·발표자료를 받은 뒤 확인할 항목이다. 이번 4배 설정에서 기대한 결과를 얻지 못했다는 회고를 4배 복원 자체의 일반적인 한계로 확대할 수는 없다.

이 예시에서는 간판, 진열대와 작은 물체의 경계·질감을 비교할 수 있다. 다만 한 장의 시각적 차이로 전체 점수 차이의 원인을 단정하지 않는다. HSV와 CLIP의 개별 점수가 없으므로 SwinIR의 이점이 어느 평가 항목에서 발생했는지도 구분할 수 없다.

SwinIR은 얕은 특징 추출, 잔차 Swin Transformer 블록을 통한 깊은 특징 추출, 고품질 이미지 재구성으로 구성된다. 이 구조 설명은 모델의 특징이며, 해당 구조가 이번 점수 차이의 직접 원인이라는 실험적 결론은 아니다. [SwinIR 논문](https://arxiv.org/abs/2108.10257)

### 점수가 높아도 선택이 간단하지 않았던 이유

색채화와 초해상도를 연결해 결과를 만드는 것뿐 아니라, 만들어진 결과를 어떤 기준으로 선택할지도 어려웠다. 당시에는 정량 점수가 높아도 시각적으로 만족스럽지 않은 결과가 있었다. 대회 점수는 비교 기준이었지만, 그 숫자만으로 출력의 시각적 품질까지 설명하기는 어려웠다.

나는 후보 출력과 제출 점수를 함께 살펴보고, 기록된 후보 중 공개 점수가 가장 높은 SwinIR 조합을 제출했다. 이 선택은 대회 평가 기준에 따른 판단이었다. 점수를 기준으로 최종 조합을 정한 것과 그 출력의 시각적 품질에 만족했는지는 구분해 돌아볼 필요가 있다.

이 경험은 본인 회고에 근거한다. 구체적으로 어떤 이미지와 모델에서 불일치가 있었는지는 아직 대조하지 않았으므로 위 예시 이미지를 그 사례로 지목하지 않았다. 실제 사례를 확보하면, 어느 부분이 만족스럽지 않았고 지표는 왜 다르게 반응했는지 연결해 설명할 수 있을 것이다.

## 5. 내가 맡은 작업과 코드로 확인되는 구현

이번에 담당 범위를 다시 정리하면 **색채화·초해상도 추론의 입출력 연결, 후보 실행과 단계별 출력·제출 점수 비교, 최종 제출 구성**이다. 이는 당시 작업에 대한 본인 설명이며, 사전학습 모델 자체를 개발하거나 재학습했다는 뜻은 아니다. 세부 코드별 작성·수정 범위는 추후 원본 자료와 대조할 예정이다. 대학원 부문 우수상은 팀 성과로 구분한다.

현재 공개 저장소에는 두 실행 스크립트가 있다.

| 파일 | 구현 |
| --- | --- |
| `src/swinir.py` | 사전학습 SwinIR 가중치 로드, RGB 변환, 2배 추론, 이미지 저장 |
| `src/submission.py` | ID 순서대로 이미지 읽기, CLIP 이미지 임베딩 정규화, CSV 저장, 폴더 압축 |

SwinIR은 `upscale=2`, `window_size=8`, `embed_dim=180`으로 생성하며 `001_classicalSR_DF2K_s64w8_SwinIR-M_x2.pth`를 사용한다. 모델을 평가 모드로 전환하고 기울기 계산 없이 추론한 뒤, 출력을 0~1 범위로 제한해 저장한다. 코드에 `.cuda()`가 직접 지정돼 있어 이 단계에는 CUDA 사용 환경이 필요하다.

제출 스크립트는 `test.csv`의 `ID` 순서를 따라 `{ID}.png`를 읽는다. OpenCLIP의 `ViT-L-14`, `pretrained="openai"` 모델로 이미지 임베딩을 추출하고 벡터의 노름으로 나눠 정규화한다. `ID`와 `vec_0`부터 시작하는 열을 가진 `embed_submission.csv`를 이미지 폴더 안에 저장한 뒤 폴더 전체를 ZIP으로 묶는다. 이 스크립트는 캡션과의 점수를 직접 계산하는 평가기는 아니다.

## 6. 결과 해석과 남은 한계

팀은 대학원 부문 우수상을 수상했고, 최종 SwinIR 조합은 비공개 평가 0.6925를 기록했다. 이 결과는 사전학습 모델을 연결하고 후보의 출력과 점수를 비교해 제출 조합을 선택한 결과다. 다만 남아 있는 결과만으로 아래 질문에 모두 답할 수 있는 것은 아니다.

### 점수 차이는 어디에서 발생했는가

후보마다 모델과 복원 배율, 크기 처리 조건이 달라 점수 차이가 모델 자체의 효과인지 특정 설정의 효과인지 분리하기 어렵다. 동일한 색채화 입력과 최종 크기를 사용하고, 중간 크기 조정 방식을 명시한 조건에서 다시 비교하면 이 차이를 더 명확히 살펴볼 수 있다.

종합 점수에도 비슷한 한계가 있다. HSV·CLIP 개별 점수가 남아 있지 않아 색 분포와 캡션 정합성 중 어떤 항목에서 차이가 났는지 알기 어렵다. 다음 비교에서는 지표를 분리해 기록하고, 필요하면 캡션의 색 단서나 객체 구성별로 결과를 나눠 살펴볼 수 있다.

### 정량 평가와 시각적 판단은 왜 달랐는가

점수와 시각적 만족도가 일치하지 않았던 경험은 있지만, 해당 사례를 모아 오류 유형별로 분석한 결과는 없다. 따라서 현재 자료로 불일치의 원인을 특정하기는 어렵다.

후속 분석에서는 실제 사례를 확보하고 시각적으로 아쉬웠던 부분을 분류한 뒤 지표와 대조하려 한다. 오류 유형은 이미 확인한 사실처럼 미리 정하지 않고, 확보한 이미지에서 관찰한 내용으로 구성해야 한다. 현재 관점에서는 이렇게 결과를 나눠 보는 과정이 종합 점수만으로 놓치는 문제를 설명하는 데 필요하다고 본다.

### 선택한 설정의 품질과 처리 비용은 어떠한가

설정별 점수와 처리 시간이 함께 기록돼 있지 않아, 선택한 조합이 얼마나 민감하게 성능을 바꾸는지 또는 더 큰 처리 비용을 요구하는지 판단하기 어렵다. 후속 비교에서는 설정과 지표별 점수, 실행 시간을 함께 기록해 품질과 처리 비용을 평가하려 한다.

이 절의 재비교·오류 분석·비용 평가는 **아직 수행하지 않은 후속 제안**이다. 사전학습 모델 추론은 이번 실험의 범위이며, 재학습하지 않았다는 사실 자체를 결함이나 미세조정의 필요성으로 해석하지 않는다.

## 7. 실행 안내와 참고 자료

가중치 경로, 실행 명령, 제출 전 확인 사항은 [프로젝트 README](https://github.com/SeokHwanHong/Projects/tree/main/inha-colorization-super-resolution)에 정리했다. 현재 공개 코드는 준비된 색채화 이미지를 받아 초해상도와 제출 파일 생성까지 수행한다.

공개 저장소에는 L-CAD와 나머지 두 복원 모델의 실행 코드가 없고 의존성 버전도 고정돼 있지 않다. 따라서 공개 코드의 존재만으로 전체 실행 성공이나 대회 당시 결과의 재현을 보장하지 않는다. 이번 수정에서도 학습·추론·성능 재평가를 수행하지 않았다.

데이터 구성·기준 설정·해상도 비교·점수·출력 이미지에 대한 팀 발표자료 **「25인챌정리본」 3~17쪽** 인용과 수상 기록은 기존 글의 근거를 유지했다. 이번에는 원본 발표자료를 다시 열람하지 않고 최신 GitHub README와 공개 코드 두 개를 직접 대조했다. 입출력 연결·후보 비교·제출 구성의 담당 범위와 당시의 어려움은 본인 설명으로 보완했으며, 세부 실행 조건과 코드별 담당은 원본 자료 수령 후 확인할 항목이다.
