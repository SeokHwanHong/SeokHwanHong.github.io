**Hi스포링**은 공공기관 체육복지 담당자가 지역별 이용 현황, 기존 프로그램과 시설 정보를 함께 확인하고 체육 프로그램 운영안을 작성하도록 돕는 서비스다. 지역 데이터를 조회하는 데서 끝나지 않고 **시설 선택 → 운영 정보 입력 → AI 검토 → 계획서 생성**까지 연결했다.

| 팀 | 설홍길 · 3인 팀 프로젝트 |

| 내 역할 | 팀장, 지역 대시보드, 프로그램 설계, 입력 예외처리, AI UI와 사용자 흐름 보완 |

## 1. 지역 데이터를 실제 기획으로 연결하기

지역에 맞는 체육 프로그램을 기획하려면 이용 실적만 보는 것으로는 부족하다. 어떤 종목의 신청이 많았는지, 비슷한 강좌가 이미 있는지, 사용할 수 있는 시설이 어디에 있는지를 함께 확인해야 한다. 서로 다른 출처의 자료를 연결하고 기획안으로 옮기는 과정 자체가 서비스의 과제였다.

따라서 지역 현황을 보여주는 대시보드와 프로그램·시설 조회를 하나의 설계 흐름 안에 배치했다. AI는 제공된 근거를 해석하고 보완할 점을 제안하며, 최종 프로그램 운영 여부는 담당자가 판단하도록 범위를 정했다.

## 2. 담당 기능: 단계 사이의 입력과 상태를 연결하기

지역 현황 대시보드와 프로그램 설계 기능을 개발하고, 설계 과정의 예외처리와 AI 결과 UI를 보완했다. 팀원은 시설 조회·AI 서버 연동·배포와 프로그램 조회·CSV 정제를 나누어 맡았다. 아래 데이터·AI·배포 구조는 팀 전체 구현이며, 모든 구성요소를 개인 작업으로 보지는 않는다.

프로그램 설계는 다음 단계로 구성했다.

1. **지역 선택:** 행정구역을 조회하고 이용 시설·강좌·신청 실적과 종목 분포를 확인한다.
2. **종목·시설 선택:** 정상 운영 후보를 검색하고 상세·교통 정보를 확인한다. 최대 20곳을 선택하며 실제 후보가 없을 때만 동의 후 시설 미정으로 진행한다.
3. **운영 정보 입력:** 프로그램명, 인원, 수강료, 대상, 기간과 내용을 입력한다.
4. **AI 검토와 계획서 생성:** 현재 입력에 유효한 AI 결과를 포함하거나, AI 없이 계획서를 생성한다. 이후 인쇄와 최근 목록 복원을 지원한다.

핵심은 화면 개수보다 **선택한 지역·시설·입력 내용이 끝까지 일치하는가**였다. 사용자가 입력을 수정했다면 이전 AI 평가를 현재 계획의 평가처럼 포함해서는 안 된다. 입력 변경 시 기존 결과는 참고용으로 남기되 계획서 포함 선택을 해제하고, 재검토 여부를 사용자가 결정하도록 했다.

## 3. 공공데이터를 서비스에 맞게 정제하기

| 자료 | 사용하는 정보와 역할 |
| --- | --- |
| 스포츠강좌이용권 이용현황 | 지역·종목별 이용 실적 집계와 AI 지역 분석의 주요 근거 |
| 공공체육시설 프로그램 | 기존 강좌 검색·비교와 Excel 내보내기 |
| 체육시설 현황 | 시설 조회와 운영 상태에 따른 후보 선택 |
| 시설 인접 교통 | 선택 시설과 연결 가능한 대중교통 정보 |

선정 데이터 대부분이 CSV로 제공되어 파일 기반 처리를 구성했다. 전국 원본을 서울 범위로 정제하고 서비스 CSV와 메모리 캐시로 조회하도록 했다. Python 데이터 처리와 웹 요청을 Django 안에서 연결하고, HTMX·JavaScript로 화면을 갱신하며 ECharts로 지역별 분포를 시각화했다.

서로 다른 CSV에 공통 식별자가 있다고 가정하지 않았다. 시설과 교통은 정규화한 시설명과 좌표를, 종목별 후보는 종목·시설유형 대응표와 지역·운영상태를 기준으로 연결했다. 연결되지 않는 정보는 확인 가능한 범위를 사용자에게 안내하도록 했다.

또한 **관측된 0과 제공되지 않은 값은 다르다.** 신청 실적이 낮다는 이유로 수요가 없다고 단정하거나 시설 수만으로 공급 부족을 판정하지 않도록 해석 범위를 제한했다. 과거 이용현황은 기획의 참고 지표이며 최신 수요나 지역 전체의 잠재 수요를 직접 측정한 값은 아니다.

### 원본 확보와 서비스 갱신을 구분하기

월간 배치는 매월 1일 01시에 원본 변경과 서비스 파일 상태를 확인하고, 필요하면 서울 데이터를 추출·검증해 발행한다. 다만 외부 최신 원본을 자동 다운로드하는 기능은 구현되어 있지 않다. 운영자가 새 원본을 확보해야 서비스도 새 자료를 반영할 수 있다.

정제 결과는 임시 파일에서 검증한 뒤 서비스 파일로 교체하고, 마지막으로 manifest에 세대와 파일 정보를 기록한다. 메모리 재적재가 실패하면 기존 정상 캐시가 있는 경우 이를 유지한다. 파일별 교체 방식이므로 여러 CSV 전체의 일괄 롤백은 보장하지 않는다는 한계도 남아 있다.

## 4. AI는 근거를 검토하는 보조 기능으로 설계하기

별도의 모델을 학습한 프로젝트는 아니다. Gemini API에 지역 집계, 선택 시설과 프로그램 입력을 전달하고 정해진 JSON 형식으로 검토 결과를 받는다. 원본 CSV 전체를 올리거나 모델의 답을 그대로 최종 의사결정으로 사용하지 않는다.

| 구분 | 지역 현황 분석 | 프로그램 검토 |
| --- | --- | --- |
| 입력 | 지역·종목 집계와 자료 기간 | 집계, 선택 시설, 사용자 입력 |
| 결과 | 지역 특징과 기획 시 확인할 점 | 강점·위험요인·개선 제안과 항목별 평가 |
| 재사용 | 서버 파일 캐시 24시간, 최대 200건 | 현재 입력에 연결된 1시간 서명 토큰 |
| 계획서 연결 | 기획 참고 | 사용자가 선택한 유효 결과만 포함 |

서버는 응답의 JSON 구조, 근거 키와 점수를 검증하고 종합 점수·등급을 계산한다. 평가할 수 있는 점수가 모두 없으면 판단 자료 부족으로 표시한다. 계획서 생성·인쇄·복원에서는 AI를 다시 호출하지 않고, 생성 당시 선택한 결과를 유지한다.

## 5. 정상 동작뿐 아니라 실패 이후의 흐름 다듬기

| 상황 | 구현한 대응 | 설계에서 중요했던 점 |
| --- | --- | --- |
| 지역 조회 응답 순서가 뒤바뀜 | 요청 버전으로 오래된 응답 무시 | 마지막 사용자 선택과 화면 결과의 일치 |
| 시설 검색 결과 없음 | 실제 후보 부재와 검색어로 인한 빈 결과 구분 | 시설 미정 진행을 잘못 허용하지 않기 |
| 날짜·인원·금액 입력 오류 | 서버에서 입력 조건 검사 | 화면 입력만 신뢰하지 않기 |
| AI 검토 후 내용 변경 | 결과 포함 해제, 입력·시설·유효시간 검증 | 다른 입력의 평가가 계획서에 섞이지 않기 |
| AI 통신·응답 오류 | 오류 안내, AI 없는 기본 계획서 허용 | 외부 API 실패가 핵심 작업을 막지 않기 |
| 최근 목록 저장 실패 | 저장 오류 처리, 생성·인쇄 흐름 유지 | 브라우저 저장과 계획서 생성 분리 |

팀 차원에서는 Gunicorn 기동 시 CSV 적재와 스케줄러 실행 시점도 조정했다. master 프로세스에서 시작한 스레드·잠금 상태가 fork 이후 맞지 않을 수 있어 워커 초기화 이후 적재와 스케줄러를 시작하도록 분리했다. 이는 로컬 기능 구현을 넘어 배포 환경의 실행 순서를 고려한 개선이었다.

## 6. 구현 결과와 검증 범위

지역 현황 조회에서 시설·프로그램 탐색, AI 검토, 운영 계획서 생성·인쇄까지 이어지는 흐름을 구현했다. 최근 계획서는 해당 브라우저에 5건을 보관하며 계정이나 기기 사이의 동기화는 제공하지 않는다.

저장소에는 대시보드·프로그램·시설 화면 캡처와 설계·인쇄 시연 기록이 있다. 2026년 9월 28일 프로젝트 개요 화면·AI 설명 관련 테스트 6건 통과가 기록되어 있지만, 이를 서비스 전체 회귀 테스트 통과로 확대해 해석하지 않았다. 일부 통합 테스트 항목은 추가 일시와 증빙이 필요한 상태다.

성과는 분석 모델의 정확도 향상이 아니라 **공공데이터 조회를 프로그램 기획 작업으로 연결한 서비스 구현**이다. 실제 기관 도입, 업무시간 단축과 정책 효과는 별도 검증이 필요하다.

## 7. 배운 점과 다음 개선

개별 기능을 구현하는 것만큼 기능 사이의 입력과 출력, 상태 변경을 맞추는 일이 중요했다. UI는 보기 좋은 화면뿐 아니라 현재 상태와 다음 행동, 오류 이후의 진행 방법을 알려주는 역할을 한다.

AI를 활용한 개발은 익숙하지 않은 기술에 접근하고 아이디어를 시도하는 데 도움이 됐다. 동시에 요구사항을 구체화하고 생성된 코드의 동작과 예외 상황을 직접 검토하는 과정이 필요했다. 다음에는 데이터 구조와 기능 간 계약을 먼저 정리하고, 핵심 사용자 흐름의 회귀 테스트를 보완하고자 한다.

- **데이터 확장:** 전국 조회를 위한 DB 스키마와 지역·종목 색인, 조회 계층 구현
- **갱신 신뢰성:** 원본 수집 단계, 독립된 예약 실행, 실패 알림과 여러 파일의 일괄 발행 보완
- **최신성 안내:** 기관 원본 기준일과 서비스 반영일 구분
- **AI 운영:** 사용자별 할당량·비용 제한, 긴 재시도와 요청 시간 제한의 충돌 개선

대관·강사 배정·접수·결제·개설 확정은 현재 범위 밖이다. 기획 지원의 범위와 실제 운영 절차를 구분하면서 확장할 계획이다.
