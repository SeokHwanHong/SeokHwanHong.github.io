Kipf·Welling의 *Semi-Supervised Classification with Graph Convolutional Networks*를 리뷰하고, 전파 규칙을 PyTorch로 구현해 GEMSEC Facebook 데이터에 적용했다. 직접 구성한 부분은 구조 특징, 정규화 희소 인접행렬, 2층 GCN과 마스크 기반 학습·시각화다. 이 글은 **논문의 방법을 코드로 옮기고 실제 데이터에 적용한 경험**을 정리한다.

## 프로젝트 한눈에 보기

| 항목 | 내용 |
| --- | --- |
| 목적 | GCN 논문의 전파 규칙 이해·구현과 Facebook 그래프 적용 |
| 입력 | 범주별 간선 CSV에서 구성한 그래프와 일부 노드의 학습 라벨 |
| 특징 | 노드 차수·정규화된 차수 집계값 2개를 고정 128차원으로 투영 |
| 모델 | 2층 GCN, `128 → 32 → 8` |

| 비교 범위 | 기준 모델 비교 실험 없음 |

## 1. 왜 GCN을 적용했는가

프로젝트의 출발점은 여러 후보의 성능을 겨뤄 모델을 고르는 것이 아니라 GCN 논문을 이해하고 구현하는 일이었다. GCN은 노드 특징과 연결 구조를 함께 입력으로 사용하고, 일부 노드의 라벨로 학습할 수 있다. 이런 방식은 연결 데이터에서 노드 분류를 시도하는 이번 적용 목적과 연결된다. 이는 현재 정리한 방법의 적합성이며 다른 모델보다 우수하다는 실험 결과는 아니다.

GEMSEC Facebook 데이터의 노드는 페이지이고 간선은 상호 “좋아요” 관계다. Artist, Athletes, Company, Government, New Sites, Politician, Public Figure, TV Show의 8개 범주별 네트워크가 제공된다. 범주별 표의 노드 합계는 134,833개지만 이를 실제 코드가 만든 하나의 그래프의 고유 노드 수로 그대로 사용하지는 않는다.

코드는 각 파일의 간선을 결합하고, 해당 파일의 카테고리를 그 파일에 등장한 노드의 라벨로 부여한다. 별도 ID 재매핑이나 역방향 간선 추가 없이 제공 데이터를 사용했다. 따라서 파일 사이 ID의 의미와 입력 간선의 저장 방식을 확인해야 실제 분류 문제를 정확하게 설명할 수 있다.

발표자료의 Cora·Citeseer·Pubmed·NELL 비교 성능은 원논문 결과 소개다. 내가 수행한 Facebook 적용 실험과 구분하며, 그 비교표로 이번 구현의 우수성을 주장하지 않는다.

## 2. 그래프 전파 규칙을 코드로 옮기기

논문의 전파 규칙은 다음과 같다.

$$
\hat{A} = \tilde{D}^{-\frac{1}{2}}(A + I)\tilde{D}^{-\frac{1}{2}},
\qquad
H^{(l+1)} = \sigma(\hat{A}H^{(l)}W^{(l)})
$$

노트북에서는 self-loop를 추가하고 정규화 계수를 계산해 희소 COO 텐서를 구성했다. 각 GCN 층은 특징에 가중치를 곱한 뒤 `torch.spmm`으로 연결에 따른 집계를 수행한다. 입력이 무방향 관계를 나타내더라도, CSV가 한 방향만 저장했는지 양방향으로 저장했는지는 별도 확인 사항이다. 정규화 식만으로 입력 인접행렬의 대칭성이 확보되는 것은 아니다.

바로 사용할 노드 속성이 없어 코드에서는 두 구조 특징을 구성했다.

$$
X_{\mathrm{raw}}=[d,\ \hat{A}d]
$$

첫 값은 입력 간선의 첫 번째 노드 열에서 집계한 차수다. 두 번째 값은 self-loop를 포함한 정규화 행렬로 차수를 집계한 값으로, 일반적인 이웃 차수의 산술평균과 다르다. 원본의 LDP 주석보다 실제 계산을 정확하게 전달하기 위해 **차수 기반 구조 특징 2개**로 설명한다.

이 특징은 `Linear(2, 128)`로 확장한다. 투영은 초기화 후 `no_grad()`로 한 번 적용하고 GCN optimizer에 포함하지 않는다. 따라서 학습을 통해 새로운 노드 속성을 추출한 층으로 설명하지 않는다. 그 위에 ReLU와 dropout을 포함한 2층 GCN을 구성했다.

## 3. 일부 라벨로 학습하고 곡선 살펴보기

학습 코드는 전체 그래프의 특징·연결을 사용해 forward를 수행하고, 학습 mask에 속한 노드에만 NLL 손실을 계산한다. 검증 노드의 라벨은 이 손실에 사용하지 않는다. 검증·테스트 노드의 연결도 사용하는 transductive 설정이며, 별도의 새로운 그래프에서 성능을 평가한 것은 아니다.

클래스별로 학습·검증 표본을 뽑는 함수가 있다. 현재 호출은 클래스당 최대 500개를 지정하지만 저장 출력은 학습 노드 2,000개이며, 주석과 발표자료의 수치도 다르다. 따라서 학습·검증 각각 4,000개를 실제 사용했다고 확정하지 않는다. 균형 샘플링 구현은 확인되지만, 이것으로 과적합을 해결했다는 비교 결과는 확보하지 못했다.

| 구성 | 현재 소스의 설정 |
| --- | --- |
| 특징 투영 | 구조 특징 2개를 고정 128차원으로 변환 |
| GCN | `128 → 32 → 8`, ReLU, dropout 0.5 |
| 최적화 | Adam, learning rate 0.001, weight decay 5×10⁻⁴ |
| 학습 | 300 epoch, 시드 42 설정 |

학습 노트북의 마지막 저장 출력은 Train Accuracy 0.6130, Validation Accuracy 0.6815다. 이는 보존 로그의 값이며 현재 소스·표본 설정과 하나의 실행으로 연결됐다고 확정하지 않았다. 별도 CSV를 읽어 만든 위 그림과 마지막 로그가 완전히 같은 실행이라는 확인도 구분해야 한다.

학습 정확도는 dropout을 적용한 갱신 전 출력으로 계산하고, 검증 정확도는 가중치 갱신 후 eval 모드에서 계산한다. 두 수치의 차이만으로 과적합 여부를 판단할 수 없다. 테스트 mask는 생성하지만 첨부·공개 노트북에는 테스트 정확도 계산이 없다.

## 4. 출력 시각화에서 말할 수 있는 범위

추론 노트북은 체크포인트를 읽고 테스트 mask에서 최대 5,000개 노드를 추출해 t-SNE를 적용한다. 입력은 은닉층이나 원시 logit이 아니라 모델의 **최종 log-softmax 출력**이다. 코드에 설정된 perplexity는 30, 반복 수는 1,000, t-SNE random state는 42다.

이번 자료 검토에서 라벨 번호와 범례 이름의 순서가 다르다는 점을 확인했다. 현재 소스는 `epoch_180` 체크포인트를 읽지만 기존 게시 그림의 파일명은 `tsne-epoch-150.png`다. 여러 epoch 그림의 동일 표본·특징 조건도 확인되지 않았다. 따라서 기존 그림을 클래스별 분리나 정확도 검증의 근거로 제시하지 않고 본문에서 제외했다. 원본 이미지 파일과 노트북 출력은 수정하지 않았다.

이 문제를 당시 발견하고 해결한 경험으로 소급하지 않는다. 투영·mask도 추론에서 다시 생성하므로, 같은 시드를 썼다는 설명 외에 학습 때의 입력과 일치하는지 확인할 근거가 필요하다.

## 5. 결과의 한계와 다음 비교

손실 감소와 검증 정확도 상승을 관찰했지만 **동일 조건의 기준 모델 비교가 없어 GCN을 사용하는 추가 이득은 판단하기 어렵다.** 전체 정확도만으로 어떤 카테고리에서 오류가 집중되는지도 충분히 설명하지 못했다.

후속 검증이 필요해지면 그래프·라벨·분할을 먼저 확인하고, 같은 특징 행렬과 분할에서 간단한 MLP와 GCN을 비교할 수 있다. Accuracy와 Macro-F1을 함께 보고 클래스별 재현율로 오류를 살펴보는 방향이다. 이미 입력 특징에 이웃 정보가 있으므로 이 비교는 그래프 정보 전체가 아닌 GCN의 추가 집계 효과를 확인한다.

이 비교는 **아직 수행하지 않은 계획**이다. 현재 프로젝트는 논문 이해·구현·적용을 보여주는 보조 경험으로 활용하며, GraphSAGE나 운영 서비스 확장을 필수 과제로 두지 않는다.

## 6. 구현 경험을 정리하며

수식의 전파 규칙을 설명하는 것과, 실제 데이터에서 어떤 노드·간선·라벨을 만들었는지 설명하는 것은 구분해야 한다. 이번 코드 검토에서는 특징의 이름보다 실제 산식, 그림의 인상보다 라벨 대응과 생성 조건을 확인할 필요를 확인했다.

이는 현재 검토에서 정리한 교훈이다. 당시의 구체적인 어려움이나 오류 해결 과정은 기억과 자료에서 확인되지 않아 새로 만들어 넣지 않았다. 모델의 구현과 그 효과의 입증도 구분해 설명하려 한다.
