LG Aimers 6기 온라인 해커톤에서 난임 시술 기록으로 임신 성공 여부를 예측했다. 팀 **뭉치네 밥버거**는 예선 상위 3%의 성적을 기록하고 오프라인 본선에 진출했다.

주요 역할은 **모델의 성능 지표와 feature importance를 참고한 파생변수 탐색**이었다. 과거 시술·임신·출산 이력의 비율, 불임 원인 플래그 합계와 정보 관측 여부, 수치·범주 표현 및 상호작용 변수를 작업했다. 팀은 CatBoost·LightGBM·AutoGluon을 활용했으며, 이 글에서는 전체 모델 개발보다 내가 맡은 후보 구성과 결과 해석에 초점을 맞춘다.

파생변수를 포함해 학습·검증하고 중요도를 살펴봤다. 기억으로는 일부 파생변수가 기존 변수보다 높은 중요도를 보일 때 포함할 후보로 판단했고, 결과와 근거를 팀원들에게 전달했다. 


## 1. 문제와 데이터: 무엇을 예측하는가

타깃은 시술 기록의 `임신 성공 여부`이며 평가 지표는 ROC-AUC다. 입력에는 연령 범주, 과거 시술·임신·출산 이력, 불임 원인, 난자·배아 수량과 경과일 등이 포함된다.

기존 집계에는 원본 train 256,351행, test 90,067행, 양성 비율 약 25.83%가 기록돼 있다. 이는 이전 자료 정리의 집계이며 이번에 원본 CSV를 다시 계산한 결과는 아니다. 노트북에서는 train의 중복 제거도 수행하므로 원본 행 수를 CV 입력 규모로 그대로 간주하지 않았다.

이 데이터에서 중요했던 것은 숫자의 크기뿐 아니라 그 값이 무엇을 기록하는지 이해하는 일이었다. `6회 이상`은 정확한 횟수가 아니고, 정보가 비어 있다는 사실은 실제 행동이 없었다는 뜻과 다르다. 파생변수를 계산하는 것과 그 값을 설명하는 것은 별도의 문제였다.

아래의 설계 의도는 현재 코드의 산식과 내 역할 설명을 연결해 정리한 것이다. 

## 2. 과거 시술·임신·출산 이력을 비율로 표현하기

총 시술·IVF·DI 각각의 시술 대비 임신 횟수와 임신 대비 출산 횟수를 작업했다. 횟수를 따로 보는 것에 더해 과거 기록 사이의 상대적 관계를 표현하려는 후보들이다.

| 후보 | 산식 | 해석 |
| --- | --- | --- |
| 총 시술 대비 임신 횟수 | 총 임신 횟수 ÷ 총 시술 횟수 | 전체 시술·임신 이력의 관계 |
| IVF 시술 대비 임신 횟수 | IVF 임신 횟수 ÷ IVF 시술 횟수 | IVF 이력 내부의 관계 |
| DI 임신 대비 출산 횟수 | DI 출산 횟수 ÷ DI 임신 횟수 | DI 임신·출산 이력의 관계 |

코드에서는 `0회`부터 `5회`를 0~5로, `6회 이상`을 6으로 바꾼 뒤 비율을 계산한다. 다음은 원본 셀 14의 일부다. 숫자 변환을 먼저 수행했다는 전제가 있으며 독립 실행 예제는 아니다.

```python
df_new['IVF 시술 대비 임신 횟수'] = np.where(
    df_new['IVF 시술 횟수_num'] > 0,
    df_new['IVF 임신 횟수_num'] / df_new['IVF 시술 횟수_num'],
    0
)
```

이 표현에는 정보 손실도 있다. `6회 이상`을 6으로 처리하므로 실제 횟수의 비율과 다를 수 있다. 분모가 0인 경우를 0으로 표현하면 ‘시술 이력 없음’과 ‘시술은 있지만 임신 기록 없음’이 같은 값으로 나타날 수 있다. 따라서 이 값은 범주화된 과거 이력의 비율이며 개인의 임상적 임신 성공확률은 아니다.

저장된 LightGBM 중요도 상위 40개 표에는 `IVF 시술 대비 임신 횟수`가 포함된다. 그러나 이 피처만 추가·제거한 동일 조건 비교가 없어 AUC 개선 폭을 분리할 수는 없다.

## 3. 불임 원인과 정보의 관측 여부 표현하기

### 여러 원인 플래그의 합계

불임 원인은 여러 열에 나뉘어 기록돼 있다. 나는 원인 플래그를 합산하는 변수도 작업했다. 노트북은 7개 플래그를 합산한 `부부 불임 원인 합계`와 세부 원인 10개를 합산한 `불임 원인 세부 합계`를 생성한다.

원본 셀 6의 일부는 다음과 같다.

```python
cause_cols1 = [
    "남성 주 불임 원인", "남성 부 불임 원인",
    "여성 주 불임 원인", "여성 부 불임 원인",
    "부부 주 불임 원인", "부부 부 불임 원인",
    "불명확 불임 원인"
]
df_new['부부 불임 원인 합계'] = df_new[cause_cols1].sum(axis=1)
```

개별 플래그와 함께 여러 원인이 동시에 기록된 양상을 요약하려는 표현으로 볼 수 있다. 하지만 합계가 크다고 임상적으로 더 심각하다는 뜻은 아니다. 원인 사이에 중복이나 상하위 관계가 있을 수 있고, 기본 합산에서는 결측값을 건너뛴다는 점도 확인해야 한다.


### 정보가 관측됐는지를 나타내는 플래그

`임신 시도 여부`도 작업한 변수지만, 이름과 실제 계산을 구분해야 한다.

```python
df_new['임신 시도 여부'] = (
    df_new['임신 시도 또는 마지막 임신 경과 연수']
    .notnull()
    .astype(int)
)
```

원본 셀 6의 이 코드는 임신 시도 행동을 판별하지 않는다. **경과 연수 정보가 관측됐는지**를 0과 1로 표현한다. 이후 원래 열의 결측값을 0으로 채우므로 값이 기록된 경우와 비어 있던 경우를 구분하는 표현으로 해석할 수 있다.

그러나 그 차이가 어떤 임상적 상황이나 기록 관행을 나타내는지는 산식만으로 확정할 수 없다. 변수명을 그대로 받아들이기보다 실제 계산이 제공하는 정보를 설명해야 하는 사례다.

## 4. 수치·범주 표현과 상호작용 탐색

이식된 배아 수, 미세주입 배아 이식 수, 배아 이식 경과일, 저장된 배아 수를 수치형과 범주형으로 표현하는 작업도 맡았다. 원본 셀 8의 핵심은 다음과 같다.

```python
df_new[col + '_num'] = pd.to_numeric(df_new[col], errors='coerce')
df_new[col + '_cate'] = df_new[col + '_num'].astype('category')
```

수치 표현은 값의 크기를, 범주 표현은 특정 값의 구분을 전달하려는 후보로 볼 수 있다. 이후 인코딩과 모델별 자료형 변환이 있어 이 함수의 출력이 최종 입력 자료형과 항상 같지는 않다.

이식 수와 경과일을 결합한 범주도 생성했다. 다음은 원본 셀 12의 일부다.

```python
df_new['이식 범주 결합'] = (
    df_new['이식된 배아 수_cate'].astype(str)
    + '_'
    + df_new['배아 이식 경과일_cate'].astype(str)
)
```

두 정보를 따로 제공하는 것에 더해 특정 조합을 하나의 범주로 전달하는 방식이다. 결측도 문자열 조합에 포함될 수 있으며, 데이터의 경과일을 배아 발달 단계와 동일시할 수는 없다.

`ICSI 효율 x 신선 난자 활용률`처럼 이미 만든 비율끼리의 곱도 작업했다. 해당 산식은 셀 6에서 확인된다. 이 역시 기록상 수량 비율의 조합이며 임상적으로 정의된 효율의 결합 효과를 입증한 것은 아니다.

### 중요도에서 관찰한 결과

저장된 표에서 `이식 범주 결합`은 다음 위치에 나타났다.

| 모델 | 저장 표에서의 순위 | 계산·해석 범위 |
| --- | ---: | --- |
| CatBoost | 4위 | fold별 모델 `feature_importances_`의 평균 |
| LightGBM | 1위 | fold별 `feature_importances_`의 평균 |
| AutoGluon | 2위 | `train_data`를 전달한 permutation importance |

이 결과는 결합 표현이 여러 모델의 저장 중요도 표에서 상위에 나타났다는 관찰이다. **피처 추가로 성능이 개선됐다는 증명은 아니다.** 원본 변수와 조합 변수가 정보를 공유하며 중요도 방식·척도도 서로 달라 절대값을 직접 비교하지 않았다.

AutoGluon의 실제 호출은 `predictor.feature_importance(data=train_data)`다. 저장 출력은 5,000행과 5회의 shuffle 사용을 보고하지만, 학습에 전달했던 데이터를 사용했으므로 평가셋의 중요도라고 설명할 수 없다.

## 5. 성능 지표와 중요도로 후보를 검토한 과정

파생변수를 포함해 학습·검증한 뒤, 기존 변수보다 높은 중요도가 나타나는 후보를 포함하는 방향으로 판단하고 그 결과를 팀원들에게 전달했다. 중요도는 후보의 활용 여부를 살펴보는 당시의 판단 근거였다.

CatBoost와 LightGBM의 평가 코드에는 `KFold(n_splits=5, shuffle=True, random_state=21)`이 사용됐다.

| 모델 | fold별 저장 AUC | 저장 평균 AUC |
| --- | --- | ---: |
| CatBoost | 0.7411 / 0.7384 / 0.7412 / 0.7402 / 0.7402 | 0.740216 |
| LightGBM | 0.7402 / 0.7377 / 0.7406 / 0.7398 / 0.7397 | 0.739596 |

평균은 더 정밀하게 저장된 값을 반올림해 표시했다. 두 값은 가깝지만 반복 시드에 따른 편차나 통계적 우열을 판단한 결과는 아니다.

노트북의 실행 번호는 순차적이지 않고 모델 설정·데이터프레임 등 공유 변수가 다시 할당된다. 현재 소스와 모든 출력이 하나의 연속 실행에서 나왔다고 확정할 수 없어 위 값은 **보존된 출력의 결과**로 제시한다.

별도 CatBoost 로그의 최고 AUC 약 0.723708은 다른 실험 기록이다.

[분할·평가 데이터·실행 상태의 확인 한계](https://github.com/SeokHwanHong/Projects/blob/main/lg-aimers-6-infertility/notes/experiment-evidence.md)

## 6. 팀의 모델 비교와 최종 제출

CatBoost, LightGBM, AutoGluon, CatBoost+LightGBM의 네 구성을 비교했고 성능 차이가 크지 않았다. 다만 동일 조건의 완전한 비교표는 확보하지 못했다.

파일에는 CatBoost·LightGBM CV 출력, AutoGluon 내부 validation 결과, 두 모델 예측의 평균 코드가 있다. AutoGluon의 내부 validation은 앞의 5-fold 평가와 다르므로 같은 조건의 모델 순위로 비교하지 않았다. `leaderboard(train_data)`의 `score_test`도 전달한 데이터에 대한 점수이며 대회 test의 점수가 아니다.

최종 제출 구성은 세 모델 예측의 동일 가중치 평균이다.

```text
p_final = (p_catboost + p_lightgbm + p_autogluon) / 3
```


## 7. 실제 어려움과 이번 코드 검토의 발견

당시 가장 어려웠던 부분은 **변수의 의미를 이해하고 결과를 해석하는 일**이었다. 시술·임신·출산 기록을 계산 가능한 형태로 만드는 것과, 그 값이 무엇을 나타내는지 설명하는 것은 달랐다. 중요도가 높게 나온 결과를 보고도 그 변수가 어떤 관계를 담았는지 설명할 필요가 있었다.


| 항목 | 확인한 내용 | 남은 확인 |
| --- | --- | --- |
| train/test 참조 | 테스트 시술 유형 전처리에 훈련 열을 대입 | - |
| 중복 산식 | 이식 수×경과일, 경과일÷연령이 다른 이름으로 반복 | 중복 제거 전후 결과 |
| 비율 분모 | 조건문과 epsilon 처리가 혼재 | 0·결측·극단값의 실제 분포 |
| 연령 변환 | 연령 범주의 첫 숫자 추출 | 범주 내 정보 손실과 미매칭 |
| 실행 상태 | 실행 번호 혼재와 공유 변수 재사용 | 소스·설정·출력의 동일 실행 연결 |

변수명도 점검했다. `배아 생존율`은 코드상 이식된 배아 수÷해동된 배아 수이며, `하루 평균 이식 배아 수`는 이식 수÷경과일이다. 각각 임상 생존율이나 실제 일별 평균으로 단정할 수 없다. `총 난자 수`는 여러 단계 수량의 합이므로 중복 가능성을 명세와 대조해야 한다.


## 8. 기록을 다시 정리하며 얻은 교훈

당시에는 중요도가 높은 파생변수를 유용한 후보로 판단하는 근거로 활용했다. 이번 정리를 통해 그 판단을 성능 개선의 증명으로 설명하려면 추가 근거가 필요하다는 점을 확인했다.

중요도는 모델이 변수를 활용한 방식을 살펴보는 단서지만, 같은 정보를 공유하는 피처 사이에서 나뉠 수 있다. 앞으로는 중요도로 후보를 탐색하되 최종 평가에는 동일 분할에서 추가·제거 전후 결과도 함께 남기려 한다.

변수명·산식·해석을 함께 기록하는 것도 중요하다. 관측 여부를 행동 여부로 부르거나 수량 비율을 생존율로 부르면 산식 이상의 의미를 전달할 수 있다.

후속 작업이 필요하다면 기존 실행 기록을 먼저 연결하고, 원본과 분리된 정리본에서 입력 참조·분모 처리·중복 산식을 점검할 것이다.
